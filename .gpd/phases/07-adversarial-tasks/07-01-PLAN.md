  <name>Task 1: Implement extended validator covering D3, D4, D6, D7, D8</name>
  <files>tools/extended_validator.py, tools/test_extended_validator.py</files>
  <action>
    Create tools/extended_validator.py that wraps validate_chamber() and adds 5 new checks:

    1. **D3 -- Ref target existence check:**
       For every source_ref in every artifact, verify the ref target exists in the chamber's artifact_index.
       This goes beyond validate_chamber()'s structural ref format check -- it tests whether the referenced artifact is actually present.
       Error code: "EXTENDED.D3_DANGLING_REF"

    2. **D4 -- Unique artifact ID enforcement:**
       Collect all artifact IDs across all stages. Verify no duplicates.
       Note: validate_chamber() checks stage_id duplicates but NOT artifact IDs within stage outputs.
       Error code: "EXTENDED.D4_DUPLICATE_ARTIFACT_ID"

    3. **D6 -- Post-seal timestamp check:**
       If chamber["sealed"] is True and chamber has a "sealed_at" timestamp, verify no stage has a "registered_at" timestamp after sealed_at.
       Error code: "EXTENDED.D6_POST_SEAL_REGISTRATION"

    4. **D7 -- Tool-call-log-to-trace completeness check:**
       Accept an optional tool_call_log (list of dicts with at minimum {"tool": str, "call_id": str}).
       For each tool call in the log, verify a corresponding artifact or trace entry exists in the chamber.
       A missing tool call in the trace indicates data was lost between tool execution and forge recording.
       Error code: "EXTENDED.D7_TRACE_DATA_LOSS"

    5. **D8 -- Content hash re-verification:**
       For every artifact that has a "content_hash" field, recompute SHA-256 on the artifact's content using the canonical serialization (CONVENTIONS.md #10: json.dumps(obj, sort_keys=True, ensure_ascii=True)) and compare.
       Error code: "EXTENDED.D8_CONTENT_HASH_MISMATCH"

    Public API:
    ```python
    def validate_chamber_extended(
        chamber: dict,
        tool_call_log: list[dict] | None = None,
    ) -> list[dict]:
        """Run validate_chamber() + all 5 extended checks.
        Returns list of error dicts: {"code": str, "message": str, "path": str, "d_type": str}
        The d_type field maps to D1-D9 taxonomy.
        """
    ```

    Also add a mapping function:
    ```python
    def classify_errors_by_dtype(errors: list[dict]) -> dict[str, list[dict]]:
        """Group validation errors by D-type (D1-D9). Returns {d_type: [errors]}."""
    ```

    Error-to-D-type mapping for existing validate_chamber() errors:
    - ABSENCE.MISSING_STATE_LABEL -> D5
    - ABSENCE.BARE_NONE -> D1
    - REF.REF_UNRESOLVED -> D2
    - CHAMBER.DUPLICATE_STAGE_ID -> D4
    - SEAL.POST_SEAL_WRITE -> D9
    (Map all existing error codes; add D-type classification as the "d_type" field.)

    Write comprehensive tests in tools/test_extended_validator.py:
    - Unit test per D-type: create a clean chamber, inject one fault, verify extended validator catches it
    - False positive test: validate 10 clean chambers, assert 0 errors from extended checks
    - Integration test: validate_chamber_extended returns superset of validate_chamber() errors
    - Edge cases: empty chamber, chamber with no artifacts, chamber with no tool_call_log

    Use existing forge_chamber.create_chamber/register_stage/seal_chamber to build test chambers.
    Use existing fault_injector.FaultInjector to inject known faults for D1-D9.
  </action>
