<task type="auto">
  <name>Task 2: Post-hoc validation and violation extraction</name>
  <files>data/campaign/raw_violations.jsonl, data/campaign/validation_report.json</files>
  <action>
    For every completed run in data/campaign/runs/:

    1. Load the run result JSON
    2. Extract the forge chamber from the run
    3. Extract the tool_call_log (for D7 check)
    4. Run validate_chamber_extended(chamber, tool_call_log) from Plan 01's extended_validator
    5. Classify each error by D-type using classify_errors_by_dtype()
    6. Write one line to raw_violations.jsonl:
       ```json
       {"run_id": "...", "task_id": "...", "category": "...", "tier": "...", "stress_level": "...", "is_control": bool, "violation_count": N, "violation_types": ["D3", "D7"], "errors": [...], "backend": "mock|openclaw"}
       ```

    After processing all runs, produce validation_report.json:
    ```json
    {
      "total_runs_validated": N,
      "total_violations_found": N,
      "runs_with_violations": N,
      "violation_rate": N/total,
      "per_dtype": {"D1": N, "D2": N, ..., "D9": N},
      "per_category": {"A1": {"runs": N, "violations": N}, ...},
      "per_stress_level": {"control": {"runs": N, "violations": N}, ...},
      "adversarial_vs_control": {
        "adversarial_runs": N,
        "adversarial_violations": N,
        "control_runs": N,
        "control_violations": N
      },
      "backend": "mock|openclaw",
      "backend_caveat": "If mock: violations are forge-layer only, not LLM-behavioral"
    }
    ```

    Manual transcript review (10 runs):
    Select the 10 highest-stress runs (Tier A, stress_level=heavy) regardless of violation status. For each:
    - Read the raw transcript
    - Look for situations where the forge pipeline SHOULD have detected a violation but didn't (false negatives)
    - Document any potential detection gaps
    - Write findings to data/campaign/transcript_review.json

    This is critical for disambiguating Outcome B (0 violations) into "violations genuinely rare" vs "detection pipeline has blind spots" per RESEARCH Section 8.2.
  </action>

    3. validation_report.json per-category counts match campaign_status.json
