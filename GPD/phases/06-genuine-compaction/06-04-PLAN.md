  <name>Task 1: Build Track C ablation framework with 9-condition matrix</name>
  <files>tools/track_c_ablation.py, tools/test_track_c_ablation.py</files>
  <action>
    Create `tools/track_c_ablation.py`:

    1. **Ablation condition matrix:**
       ```python
       INSTRUCTION_VARIANTS = {
           "default": None,  # Use Anthropic's default summarization prompt
           "provenance_aware": (
               "Preserve all artifact IDs (strings matching 'artifact:*:r*'), "
               "all source_ref links between artifacts, and all absence state labels. "
               "These are provenance metadata that must survive summarization intact. "
               "Also preserve task state, next steps, and key decisions."
           ),
           "minimal": "Summarize briefly. Focus on key outcomes only.",
       }

       THRESHOLD_LEVELS = [50_000, 80_000, 120_000]  # tokens

       MODEL_VARIANTS = ["claude-sonnet-4-20250514", "claude-opus-4-20250514"]
       ```

    2. **AblationConfig dataclass:**
       - condition_id: str (e.g., "C-default-80K-sonnet")
       - instructions: str | None
       - threshold: int
       - model: str
       - trials_per_condition: int (default 10)
       - task_template_name: str (cycles through A1/A2/A3)

    3. **AblationRunner class:**
       - `generate_conditions() -> list[AblationConfig]`: Generate all 9 instruction x threshold conditions (model ablation is separate). Returns 9 configs for Sonnet, plus optional 9 for Opus.
       - `run_condition(config: AblationConfig, n_trials: int) -> list[TrialResult]`: Run N trials for one condition using GenuineCompactionRunner.
       - `run_full_ablation(n_per_condition: int = 10) -> AblationResults`: Run all conditions sequentially.
       - `aggregate_condition(results: list[TrialResult]) -> ConditionSummary`: Compute mean, std, CI for all metrics within one condition.
       - `compute_deltas(summaries: dict[str, ConditionSummary]) -> dict`: Compute provenance_aware_delta = survival(provenance_aware) - survival(default) at each threshold level. Also compute threshold effect and model effect.
       - `export_results(path: str)`: Write JSONL per condition + aggregated JSON summary.

    4. **Multiple comparisons:** When comparing 3 instruction variants:
       - Apply Bonferroni correction (alpha = 0.05/3 = 0.0167)
       - Report both corrected and uncorrected p-values
       - Use bootstrap permutation test for between-group comparisons

    5. **Dry-run mode:** Uses GenuineCompactionRunner in dry-run mode. All conditions produce synthetic data. Validates the aggregation and delta computation pipeline.

    Create `tools/test_track_c_ablation.py` with:
    - Condition generation: verify 9 conditions (3 x 3) produced
    - Dry-run of single condition: verify metrics computed
    - Aggregation: verify mean/std/CI computed correctly on known inputs
    - Delta computation: verify provenance_aware - default computed correctly
    - Bonferroni correction: verify corrected p-values
    - At least 10 test functions
  </action>
  <verify>
    1. All tests pass: `python3 -m pytest tools/test_track_c_ablation.py -v`

  <name>Task 2: Build SWE-Bench forge agent scaffold with provenance instrumentation</name>
  <files>tools/swebench_forge_agent.py, tools/test_swebench_forge_agent.py</files>
  <action>
    Create `tools/swebench_forge_agent.py` -- a forge-instrumented coding agent designed for SWE-Bench tasks:

    1. **SWEBenchForgeAgent class:**
       - `__init__(issue_description: str, repo_context: str, run_id: str, model: str, threshold: int)`
       - Initializes forge chamber: `chamber:swebench:{run_id}:v1`
       - Uses compact_20260112 API with pause_after_compaction

    2. **Agent loop (5 phases, each producing forge artifacts):**
       a. **Understand:** Read issue description. Produce artifact: `artifact:{run_id}:stage:understand:r1`
          - source_refs: [] (root artifact)
       b. **Plan:** Design solution approach. Produce artifact: `artifact:{run_id}:stage:plan:r1`
          - source_refs: [understand artifact]
       c. **Implement:** Write code patches. Produce artifact per file: `artifact:{run_id}:stage:impl:{filename}:r1`
          - source_refs: [plan artifact]
       d. **Test:** Run test suite. Produce artifact: `artifact:{run_id}:stage:test:r1`
          - source_refs: [all impl artifacts]
       e. **Revise:** If tests fail, iterate. Produce: `artifact:{run_id}:stage:revise:{n}:r1`
          - source_refs: [test artifact, relevant impl artifacts]
          - Revision loop up to 3 iterations

    3. **Forge instrumentation at each phase:**
       - Create forge artifact via create_v1_stage_artifact
       - Register in chamber via register_stage
       - Embed artifact IDs in assistant messages for compaction survival tracking
       - Track provenance depth (should reach >= 5 for any task with revisions)

    4. **Compaction event handling:**
       - When stop_reason == "compaction": capture boundary via genuine_compaction_runner.capture_boundary
       - Log compaction event to findings ledger
       - Continue conversation from compaction summary

    5. **Dry-run mode:** Instead of API calls:
       - Generate synthetic responses for each phase
       - Simulate a compaction event after phase 3 (implementation)
       - Produce complete forge chamber with all artifacts and provenance chains

    6. **Output:** TrialResult with:
       - task_id (SWE-Bench task identifier)
       - agent phases completed
       - forge chamber (serialized)
       - compaction events (list)
       - aggregate metrics
       - task_success (True/False -- from SWE-Bench eval, only available with Docker)

    NOTE: This plan builds the SCAFFOLD only. Actual SWE-Bench execution requires Docker setup (swebench package, Docker Desktop, 120GB disk). That is researcher_setup for a future plan. The scaffold validates forge instrumentation in dry-run mode.

    - Dry-run execution: verify 5 phases produce artifacts
    - Provenance chain validation: understand -> plan -> impl -> test -> revise
    - Provenance depth >= 4 on simple task (no revisions), >= 5 with revisions
    - Chamber validation: zero errors after dry-run
    - Compaction event capture: simulated compaction produces valid snapshot
    - At least 8 test functions
  </action>
