Purpose: The natural violation campaign (Plans 03-04) cannot find violations that the pipeline cannot detect. This plan closes the detection gap identified in v1.0 (CC-009) where post-hoc detection missed D3/D4/D6/D7/D8 because they require checks beyond structural validation. D9 is already caught at runtime by ForgeChamberError; this plan adds post-hoc timestamp-based detection.
Output: extended_validator.py with full D1-D9 detection (canonical taxonomy per CONVENTIONS.md #8 and fault_injector.py), test suite, injection sanity check results confirming >= 90% per-type detection.

    Create tools/extended_validator.py that wraps validate_chamber() and adds 6 new checks.

    CRITICAL: The D-type labels MUST match the canonical taxonomy in CONVENTIONS.md #8 and fault_injector.py:
    - D3 = Corrupted hashes (SHA-256 mismatch on round-trip)
    - D4 = Fake source refs (refs that resolve but to wrong artifact)
    - D6 = Illegal state transition (violates transition matrix)
    - D7 = Forge trace compression data loss (cursor-advancement refs silently dropped)
    - D8 = Context pressure corruption (truncated output simulating memory pressure)
    - D9 = Post-seal registration (stage registered after chamber seal)

    The 6 new checks, labeled by their CANONICAL D-type:

    1. **D3 -- Content hash re-verification:**
       For every artifact that has a "hash" field, recompute SHA-256 on the artifact's content using the canonical serialization (CONVENTIONS.md #10: json.dumps(obj, sort_keys=True, ensure_ascii=True)) and compare.
       This detects post-hash modification (inject_d3_corrupted_hashes modifies output AFTER hash computation).
       Error code: "EXTENDED.D3_CONTENT_HASH_MISMATCH"

    2. **D4 -- Fake source ref detection:**
       For every artifact, check whether source_refs point to semantically correct parents (not just any valid ID).
       Heuristic: if a ref points to an artifact that was registered AFTER the referencing artifact, it's likely fake.
       Also check for self-referencing loops (artifact refs itself).
       Note: full D4 detection requires semantic context; this is a structural approximation.
       Error code: "EXTENDED.D4_SUSPICIOUS_REF_TARGET"

    3. **D6 -- Illegal state transition detection:**
       For each pair of consecutive stages (i, i+1) where both have an output_state field,
       call validate_transition(stages[i].artifact.output_state, stages[i+1].artifact.output_state)
       from forge_nulls.py. If validate_transition() returns False, the transition is illegal per
       the TRANSITION_TABLE (64 entries, 19 illegal).
       IMPORTANT: validate_chamber()'s CHAMBER.DUPLICATE_STAGE_ID, INDEX_NOT_MONOTONIC, and
       INDEX_DESYNC are structural integrity checks (ordering, uniqueness), NOT state transition
       legality checks. They do NOT detect D6. This check is the only D6 detector.
       Error code: "EXTENDED.D6_ILLEGAL_TRANSITION"

    4. **D7 -- Tool-call-log-to-trace completeness check:**
       Accept an optional tool_call_log (list of dicts with at minimum {"tool": str, "call_id": str}).
       For each tool call in the log, verify a corresponding artifact or trace entry exists in the chamber.
       A missing tool call in the trace indicates data was lost between tool execution and forge recording.
       Error code: "EXTENDED.D7_TRACE_DATA_LOSS"

    5. **D8 -- Content truncation / corruption detection:**
       For every artifact with non-null output, check for truncation signatures: (a) output ends mid-word or mid-JSON,
       (b) output length suspiciously shorter than summary references suggest, (c) known truncation markers like "[TRUNCATED".
       Also verify summary_hash matches recomputed hash (corruption propagates to summaries).
       Error code: "EXTENDED.D8_CONTENT_TRUNCATION"

    6. **D9 -- Post-seal timestamp check:**
       If chamber status is "sealed" and chamber has a "sealed_at" timestamp, verify no stage has a "registered_at" timestamp after sealed_at.
       This detects post-seal registration that bypassed the normal seal guard.
       Error code: "EXTENDED.D9_POST_SEAL_TIMESTAMP"

    Public API:
    ```python
    def validate_chamber_extended(
        chamber: dict,
        tool_call_log: list[dict] | None = None,
    ) -> list[dict]:
        """Run validate_chamber() + all 6 extended checks.
        Returns list of error dicts: {"code": str, "message": str, "path": str, "d_type": str}
        The d_type field maps to D1-D9 canonical taxonomy (CONVENTIONS.md #8).
        """
    ```

    Also add a mapping function:

    ```python
        """Group validation errors by D-type (D1-D9). Returns {d_type: [errors]}."""
    ```

    Error-to-D-type mapping for existing validate_chamber() error codes (enumerate from forge_chamber.py and forge_v1_bridge.py):
    - ABSENCE.MISSING_STATE_LABEL -> D5 (missing state label on null output)
    - REF.REF_UNRESOLVED -> D2 (broken provenance: ref not in artifact_index)
    - CHAMBER.DUPLICATE_STAGE_ID -> "STRUCTURAL" (structural integrity: duplicate stage registration; NOT D6)
    - CHAMBER.INDEX_NOT_MONOTONIC -> "STRUCTURAL" (structural integrity: stage ordering violated; NOT D6)
    - CHAMBER.INDEX_DESYNC -> "STRUCTURAL" (structural integrity: artifact_index inconsistent; NOT D6)
    - REVISION.REV_BLOCK_SCHEMA -> "SCHEMA" (structural schema error, not a single D-type; classify as the closest match based on the specific field that failed -- e.g., hash field -> D3, ref field -> D2)
    - SUMMARY.MISSING_SOURCE_REFS -> D2 (broken provenance in summary)

    CRITICAL NOTE on D6: CHAMBER.DUPLICATE_STAGE_ID, INDEX_NOT_MONOTONIC, and INDEX_DESYNC
    are structural integrity checks (ordering, uniqueness), NOT state transition legality checks.
    D6 per CONVENTIONS.md #8 is "Illegal state transition (violates transition matrix)" -- i.e.,
    an illegal (from_state, to_state) pair per TRANSITION_TABLE in forge_nulls.py. D6 detection
    is handled EXCLUSIVELY by the new EXTENDED.D6_ILLEGAL_TRANSITION check (item 3 above).
    The STRUCTURAL errors do not map to any D-type in the D1-D9 taxonomy.

    Note: The error codes ABSENCE.BARE_NONE and SEAL.POST_SEAL_WRITE do NOT exist in the current codebase.
    D1 (null collapse) is detected by ABSENCE.MISSING_STATE_LABEL when output is None without output_state.
    D9 (post-seal registration) is detected at runtime by ForgeChamberError exception in register_stage(), not by a validation error code. The new EXTENDED.D9_POST_SEAL_TIMESTAMP check adds post-hoc detection.
