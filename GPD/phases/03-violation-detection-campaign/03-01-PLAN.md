  <action>
    Build a FaultInjector class that wraps OpenClawAdapter chamber output to inject each of the 9 structural fault types at configurable positions. The injector operates on sealed chambers (post-hoc), not during live processing.

    1. Create tools/fault_injector.py with class FaultInjector:

       Constructor takes a sealed chamber dict (from OpenClawAdapter.finalize() or process_ledger()).

       Implement 9 injection methods, each returning a MODIFIED COPY of the chamber (never mutate original):

       - inject_d1_null_collapse(stage_index): Replace typed absence output {value: null, state: "not_generated"} with bare None on the specified stage. Strips the output_state field.
       - inject_d2_broken_provenance(stage_index): Replace source_refs on the specified stage with refs to nonexistent artifact IDs (e.g., "artifact:ghost:stage:phantom:r1").
       - inject_d3_corrupted_hashes(stage_index): Modify the artifact content field AFTER hash computation so SHA-256 no longer matches. Use the hash integrity convention (#10): json.dumps(obj, sort_keys=True, ensure_ascii=True).
       - inject_d4_fake_source_refs(stage_index): Replace source_refs with refs that are syntactically valid artifact IDs AND exist in the chamber's artifact_index, but point to the WRONG artifact (a different stage than the logical parent).
       - inject_d5_missing_state_label(stage_index): Remove the output_state field from a stage whose output is null, leaving ambiguous absence (no typed absence state).
       - inject_d6_illegal_transition(stage_index): Force an illegal state transition by changing a stage's output_state to create a (from, to) pair that TRANSITION_TABLE classifies as illegal. Use validate_transition() from forge_nulls.py to confirm the transition is indeed illegal.
       - inject_d7_compaction_data_loss(stage_index): During a cursor-advancement artifact (compact type), silently drop some task_ids from the source_refs list. The remaining refs still form a valid-looking ref list, but information is lost.
       - inject_d8_context_pressure_corruption(stage_index): Truncate artifact output content mid-string (simulate memory pressure corruption). The output is non-null but incomplete, and if the stage has a summary, corrupt the summary content too.
       - inject_d9_post_seal_registration(): After the chamber is sealed, attempt to register a new stage. This violates chamber seal semantics (sealed chambers are immutable).

    2. Implement verify_injection(original_chamber, injected_chamber, fault_type) -> dict:
       Returns {"verified": bool, "original_valid": bool, "injected_invalid": bool, "errors": list}.
       - original_valid: validate_chamber(original) returns [] (no errors)
       - injected_invalid: validate_chamber(injected) returns non-empty errors OR the specific corruption is detectable by forge validation
       - verified: original_valid AND injected_invalid

       CRITICAL: For D7 (silent ref loss), the remaining refs may still form a valid DAG. If validate_chamber() does not catch D7, document this as a forge coverage gap -- do NOT add new validation logic in this plan. The gap itself is a finding.

    3. Implement inject_random(chamber, fault_type, seed=None) -> dict:
       Randomly selects a valid stage_index for the given fault type and injects. Uses random.Random(seed) for reproducibility.

    4. Create tools/test_fault_injector.py with tests:

       For each D1-D9:
       - test_dN_produces_corrupted_artifact: Inject into a known-good chamber, verify the injected chamber differs from original at the expected location.
       - test_dN_verify_injection: verify_injection() returns verified=True (original valid, injected invalid) OR documents the gap for D7.

       D7-D9 calibration tests (the NEW fault types not in MockLM):
       - test_d7_detected_by_forge: Inject D7 into a chamber with cursor-advancement artifacts. Run validate_chamber(). Document whether detected or not. If NOT detected, the test PASSES but the result is "gap identified" (not a test failure -- it is a finding about forge's coverage).
       - test_d8_detected_by_forge: Inject D8. Run validate_chamber(). Truncated content may or may not be caught depending on whether forge validates content integrity.
       - test_d9_detected_by_forge: Inject D9. Registering a stage after seal MUST raise ForgeChamberError (this is enforced by seal_chamber).

       Regression on D1-D6: Compare detection behavior against MockLM ceiling:
       - test_d1_d6_match_mocklm_detection: For each D1-D6, inject and verify that the SAME error type is raised as in MockLM (D1=ForgeNullError or missing state, D2=ForgeRefError or unresolvable ref, D3-D6=ForgeChamberError or validation error).

       Bootstrap CI validation test:
       - test_bootstrap_ci_coverage: Generate 1000 samples of size 20 from Binomial(20, 0.7). Compute bootstrap 95% CI for each. Verify coverage >= 93%.
       - test_clopper_pearson_boundaries: Verify CI at 0/10 has upper bound ~0.308. Verify CI at 10/10 has lower bound ~0.692.

    IMPORTANT CONSTRAINTS:
    - Do NOT modify openclaw_adapter.py, forge_nulls.py, forge_chamber.py, or any existing forge tools. The injector wraps their output.
    - Use deepcopy for all chamber mutations. Never mutate the original.
    - Import TRANSITION_TABLE and validate_transition from forge_nulls for D6.
    - Import validate_chamber from forge_chamber for verification.
    - All detection metrics are dimensionless ratios in [0, 1]. All counts are non-negative integers.
    - Follow convention #6: always qualify "compaction" (forge trace compression vs LLM context-window compaction).

    - D7-D9 are NEW: no MockLM anchor exists. Document detection results as new findings.

  <name>Task 2: Build campaign orchestrator with three-tier comparison and statistical framework</name>
  <files>tools/detection_campaign.py</files>
  <action>
    Build a DetectionCampaign class that orchestrates the full injection and detection campaign, building on FaultInjector and the Phase 2 measurement framework.

    1. Create tools/detection_campaign.py with class DetectionCampaign:

       Constructor takes:
       - ledger_path: Path to queue_ledger.jsonl (real data)
       - task_corpus: List of task IDs to include
       - seed: int (default 42) for reproducible randomization
       - n_injections_per_type: int (default 10, minimum 10)

    2. Implement schedule_injections() -> list[InjectionSpec]:
       - For each fault type D1-D9, schedule n_injections_per_type injections.
       - Randomize injection position within each run (early/middle/late stage indices).
       - Balance across tasks: no single task gets > 30% of total injections for any fault type.
       - Each InjectionSpec: {fault_type: str, task_id: str, stage_index: int, position: "early"|"middle"|"late"}.
       - Total: >= 90 injections (9 types x 10 each).
       - Use random.Random(seed) for deterministic scheduling.

    3. Implement run_three_tier_comparison(injected_chamber) -> TierResult:
       For each injected chamber, run it through all three tiers:
       - Uninstrumented: No validation (always returns 0 detections -- this is the floor).
       - Structured logging: Schema validation only (from structured_logging_baseline.py). Detects schema violations but not structural violations.
       - Forge: Full structural validation via validate_chamber() + verify_trace(). Detects structural violations.

       Record per-injection: {fault_type, task_id, stage_index, uninstrumented_detected: bool, structured_detected: bool, forge_detected: bool, forge_error_type: str|null, forge_error_detail: str|null}.

    4. Implement compute_detection_rates(results) -> DetectionReport:
       - Per-fault-type detection rate per tier: violations_detected / total_injections for that type.
       - Aggregate detection rate per tier: total_detected / total_injections across all types.
       - Differential: delta_forge_uninstrumented = forge_rate - uninstrumented_rate. delta_forge_structured = forge_rate - structured_rate.
       - For each rate: if rate is 0/n or n/n, use Clopper-Pearson exact binomial CI. Otherwise, use bootstrap 95% CI (B=10000, seed=42).
       - Report the D7-D9 detection rates separately (new fault types without MockLM anchor).

    5. Implement separate_injected_natural(all_detections) -> (list, list):
       Given all validation errors from a campaign run, separate:
       - Injected detections: errors at known injection points (matched by stage_index and fault_type).
       - Natural detections: errors NOT at any known injection point.
       This separation is CRITICAL for the contract: fp-synthetic-only forbids counting injected faults as natural violations.

    6. Implement run_clean_campaign(n_runs_per_task) -> CleanResults:
       Run the ledger through forge validation WITHOUT any injections.
       - n_runs_per_task >= 5 for short tasks (FPR measurement), >= 5 for long tasks (natural violation exposure).
       - Record all validation errors. These are candidates for natural violations.
       - Compute false_positive_rate = errors_on_clean_runs / total_clean_runs.
       - If FPR > 5%, flag as red flag: forge validation may be too strict for real data (Pitfall 4 from RESEARCH.md).

    7. Implement generate_campaign_report(injection_results, clean_results) -> dict:
       JSON-serializable report with:
       - injection_summary: per-type detection rates with CIs, aggregate rate, three-tier comparison.
       - clean_summary: FPR with CI, natural violation candidates (if any).
       - anchor_comparison: D1-D6 detection rate vs MockLM ceiling (6/6). D7-D9 as new findings.
       - methodology: n_injections, n_clean_runs, seed, CI method, data source.
       - separated: injected_detections count, natural_detections count, natural_detections details.

    8. Implement run_full_campaign() -> dict:
       End-to-end: schedule -> inject -> compare -> compute -> separate -> report.
       Also supports dry_run=True mode that schedules and validates setup without executing.

    STATISTICAL FRAMEWORK:
    - bootstrap_ci(values, n_boot=10000, seed=42, alpha=0.05) -> (lower, upper): Percentile bootstrap.
    - clopper_pearson_ci(k, n, alpha=0.05) -> (lower, upper): Exact binomial CI using scipy.stats.beta.ppf().
    - select_ci(k, n, values, alpha=0.05) -> (lower, upper, method): Auto-selects bootstrap or Clopper-Pearson based on whether k/n is at boundary (0 or n).

    Reuse bootstrap_ci() from baseline_measurement.py if the interface is compatible. If not, implement a fresh version following the same convention (B=10000, seed=42, percentile method).

    ANCHOR COMPARISON (ref-mock-experiment):
    - generate_campaign_report() MUST include a section comparing D1-D6 aggregate detection rate against MockLM ceiling (6/6 = 100%).
    - If D1-D6 aggregate rate < 100%, the report documents which fault types were missed and why.
    - D7-D9 results are reported separately as "new findings beyond MockLM scope."

    FORBIDDEN PROXY GUARDS:
    - separate_injected_natural() enforces fp-synthetic-only: injected and natural detections are never aggregated in the headline metric.
    - Task corpus includes L1-L3 (long tasks) to address fp-short-tasks.
